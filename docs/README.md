# docs/ — Как читать этот репозиторий (6-шаговая логика развёртывания)

## Логика репозитория (нарратив)

Репозиторий разворачивается перед читателем в **6 шагов** — как ответ на профессиональный вызов:

| Шаг | Документ | Один абзац |
|---|---|---|
| **1. Проверка входных данных** | [`01_dataset_scrutiny.md`](01_dataset_scrutiny.md) | Полученный датасет (100 «слабых сигналов») проверен документально: заметная доля строк (по оценкам ~25%) **заведомо не является** слабыми сигналами (состоявшиеся рынки, стандарты, проблемы, зрелые обещания). Приводим протокол с фактами. Это снижает доверие к разметке «+» как ground truth. |
| **2. Собственный эталон** | [`02_benchmark_dataset.md`](02_benchmark_dataset.md) | Реакция: в отсутствие надёжного обучающего материала построен **собственный эталонный датасет-бэктест** (экспертный домен — сверхпроводимость): сигналы 2018 года задокументированные в roadmap'ах → документально подтверждённый исход 2026. Это диагноз по уликам, а не мнение. |
| **3. Почему не ML** | [`03_why_literature_not_ml.md`](03_why_literature_not_ml.md) | Достоточно большой для data-driven моделей датасет за время хакатона не собрать (не хватает порядков), поэтому сложные ML-модели бессмысленны. Вместо этого — **систематизация литературы** (обработано более 100 источников): какие гипотезы выявления трендов известны миру. |
| **4. Проверка на эталоне → синтез** | [`04_synthesized_model.md`](04_synthesized_model.md) | Литературные модели прогоняются на нашем эталоне: видим их сильные и слабые стороны → **синтезируем собственную** двухэтапную схему (скрининг → верификация). |
| **5. Перекрёстная проверка** | [`05_crosscheck_on_provided_100.md`](05_crosscheck_on_provided_100.md) | Синтезированную модель точечно проверяем на тех строках из их 100, которые выглядят как настоящие слабые сигналы → демонстрация применимости вне калибровочного домена. |
| **6. Полный метод** | [`06_proposed_methodology.md`](06_proposed_methodology.md) | Пошаговый пайплайн определения слабого сигнала зарождающегося технологического тренда: двухэтапный конвейер (скрининг novelty×growth×impact → верификация: проблема → класс-проблема → нормированный рост → патенты/игроки → конференции → гранты → IPO/M&A → вердикт impact×adoption×conversion) + операционный чек-лист сбора кейса [`CASE_BUILDING_GUIDE.md`](CASE_BUILDING_GUIDE.md). |

## Как связаны шаги и ТЗ

- **Шаг 1** отвечает на неудобный вопрос «почему мы не доверяем датасету заказчика» — фактами, а не словами;
- **Шаги 2-4** показывают **научно-обоснованный подход в условиях малых данных** (калибровка на
  известных исходах = наша главная ценность для жюри);
- **Шаг 5** демонстрирует ровно то, что требует ТЗ: отсев зрелого/хайпа/шума/стандартов и
  применимость вне рамок датасета.
- **Шаг 6** описание полного пайплайна определения слабого сигнала зарождающегося технологического тренда (двухэтапный конвейер + операционный чек-лист `CASE_BUILDING_GUIDE.md`); собирает шаги 1-5 в единый метод.
