## Суть работы
Разъясняет путаницу между **Horizon Scanning (HS)** и **Foresight**: они НЕ идентичны.
- **Horizon Scanning** — начало любой проспективной деятельности, может быть **автоматизированным stand-alone** подходом для идентификации «нового в науке и технологиях» (сбор сигналов, часто машинный);
- **Foresight** — процесс-ориентирован, ВСЕГДА включает фазу HS, но добавляет **смыслообразование (sense-making), дебаты, построение стратегии**;
- HS = «сканирование — это не дебаты и не стратегия»;
- Модель EU «Foresight Cycle» (EFFLA): scanning → sense-making → strategy.

## Значимость для проекта (фичи + гипотезы)

### Для позиционирования сервиса (важно для жюри)
| Наш сервис | Что это по Cuhls |
|---|---|
| Ввод направления → список зарождающихся трендов с аналитикой | **Horizon Scanning** (автоматизированное сканирование) |
| Мотивация/кейс-пример/источник | Частичный sense-making (но не дебаты/стратегия) |

**Честный вывод для питча:** наш продукт — автоматизированный **Horizon Scanning**, а НЕ полный Foresight. Его ценность — «подать сигналы наверх», финальное решение за человеком (согласуется с нашей методологией: шаг 3 требует эксперта!). Это сильный аргумент честности — мы не обещаем «предсказание», а «сканирование + аналитику».

### Фичи/гипотезы (меньше, чем у методов; статья методологическая)
- **H-CU1 (автоматизация vs экспертиза):** автоматизированное сканирование эффективно для СБОРА, но не для СМЫСЛА — подтверждает наш принцип «LLM = генератор гипотез, не судья» (METHODOLOGY §4г);
- **H-CU2 (роль человека):** сервис должен явно разделять «сигнал найден» (машина) и «сигнал значим» (человек/эксперт) — фича «confidence/экспертная метка» в выдаче.
