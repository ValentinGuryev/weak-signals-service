## Суть работы (2–3 предложения)

Представлен **AIDA Dashboard** — веб-приложение для анализа и сравнения научных конференций (разработано совместно со **Springer Nature** для редакционной команды). Инструмент сочетает машинное обучение, семантические технологии и визуальную аналитику на основе **AIDA Knowledge Graph** и **Computer Science Ontology (CSO, 14K тем)**. Три ключевые фичи: сравнение конференций в полях/временных окнах; характеристика конференций по 14K темам CSO; оценка вовлечённости индустрии (66 секторов INDUSO). Оценка: F1 91.8% (фокус-области) и 87.5% (промышленные секторы), SUS 87.5/100 (A+).

## 1. Введение и мотивация

- Научные конференции необходимы для развития сообществ, кросс-опыления идей, моста академия-индустрия, распространения новых результатов. В CS конференции — первая площадка публикаций.
- **Проблема:** существующие инструменты (Semantic Scholar, Dimensions, Scopus, Web of Science, AMiner) дают ограниченную аналитику по конференциям: грубая таксономия полей, одна метрика (h5-index), мало конференций (например, 20), нет эволюции тем, нет вовлечённости индустрии.
- **Мотивация индустрии:** tech-компании (Alphabet, Facebook/Meta, Microsoft, IBM) активно производят фундаментальные подходы в Neural Networks; коллаборации с не-академическими партнёрами — важная метрика для финансирующих агентств (отчёты в EU).
- **Цель:** AIDA Dashboard для анализа и сравнения конференций (ML + семантические технологии + визуальная аналитика), разработан со Springer Nature для редакторов; обобщён до инструмента для CS-исследователей.

### Три новые фичи
1. **Сравнение и ранжирование конференций** в конкретных полях (Digital Libraries) по разным метрикам и временным окнам (последние 5 лет).
2. **Характеристика по 14K темам CSO** — гранулярное представление тем и их эволюции во времени. Пример: тема «Machine Learning» состоит из 760 под-тем («Denoising Autoencoders», «Fuzzy Neural Networks») → и высокоуровневое представление для не-экспертов, и зум в конкретные концепты.
3. **Вовлечённость индустрии:** (i) влияние коммерческих организаций во времени; (ii) соотношение публикаций индустрии/академии/коллабораций; (iii) категоризация по **66 промышленным секторам** INDUSO (automotive, financial, energy, electronics).

### Основа и данные
- AIDA KG: Microsoft Academic Graph (MAG), Dimensions, DBpedia, CSO, INDUSO, GRID.
- Два unsupervised классификатора (темы, промсектора) по абстрактам, метаданным, DBpedia и онтологиям.
- Покрытие прототипа: 1990 — mid-2021; планировался релиз 1.0 в марте 2022.
- **Вклады:** AIDA Dashboard; пайплайн семантически обогащённой аналитики (2 классификатора); количественная оценка; качественная оценка (user study, 10 сеньор-исследователей); **AIDA Conference dataset — 3 509 конференций CS**.

## 2. Related work

### 2.1 SKG (Scientific Knowledge Graphs)
- MAG (250M+ публикаций, 2021), Semantic Scholar Open Research Corpus (~185M), OpenCitations (55M публикаций / 655M цитирований), Scopus (80M+), AMiner Graph (200M+), Open Academic Graph (208M MAG + 172M AMiner + 91M связей), DBLP (5.5M статей, 2.7M авторов, 5.4K конференций), CORE (24M), OpenAIRE DOIboost, Dimensions (119M публикаций, 6M грантов, 137M патентов).
- Семантические KG: Semantic Publishing, Linked Data Cloud, биологические KB, workflow-онтологии, nano-/micropublications; онтологии SWRC, BIBO, BiDO, FABIO, SPAR, CSO, SKGO.
- **Выбор MAG как основного источника:** самый полный публичный KG + хорошее представление конференций (серии и выпуски). После декоммиссии MAG (после 2021) — переход на Dimensions + DBLP (план устойчивости).

### 2.2 Инструменты оценки конференций
- Microsoft Academic: аналитика конференций (число статей, цитаты, related conferences, темы, авторы, организации), но НЕТ сравнения и эволюции тем во времени.
- AMiner, Semantic Scholar: просмотр конференций, но только главные авторы/статьи.
- Scholia (Wikidata): профили, но данные неполны; темы — для серии в целом (не эволюция).
- Scopus: связывает статьи с proceedings, но не агрегирует в конференции.
- Lens.org: интеграция MAG, Crossref, Core, PubMed; без анализа конференций как сущностей.

### 2.3 Другие наукометрические инструменты
- **VOSviewer** (Van Eck et al.): сети соавторства/ко-встречаемости/цитирования.
- Инструмент Guilarte et al.: поиск экспертов-рецензентов через цитатные связи.
- **SciKGraph** (Tosi et al.): семантические технологии + NLP для структурирования исследовательских полей; KG концептов по ко-встречаемости; кластеризация областей.
- Общее: не фокусируются на конференциях; не учитывают вовлечённость индустрии. AIDA Dashboard — интегрированный набор аналитик для конференций.

## 3. AIDA Knowledge Graph

- Описывает публикации и патенты CS по темам, промсекторам, типам аффилиаций.
- **21M публикаций (MAG) + 8M патентов (Dimensions)** с темами CSO; **5.1M публикаций + 5.6M патентов** с типами аффилиаций и 66 секторами.
- Текущая версия дашборда — только публикации (патенты для будущих анализов академия-индустрия).
- **Пайплайн (3 шага):** (i) классификация статей темами CSO; (ii) определение типов аффилиаций; (iii) классификация промсекторами INDUSO.

### 3.1 Классификация тем
- CSO: 14K тем, 159K отношений (совместно со Springer Nature).
- Выборка: все публикации MAG с FoS «Computer Science» + патенты Dimensions по IPC/FoR → 20M публикаций + 8M патентов.
- **CSO Classifier** (unsupervised, open-source Python): синтаксический модуль (n-граммы vs метки CSO через Levenshtein) + семантический модуль (POS tagging, Word2Vec на 4.6M публикаций CS из MAG: skipgram, embedding 128, window 10, min-count 10, max-iter 5; relevance score = frequency × diversity; elbow method) → + супер-темы CSO (статья «neural networks» → также «machine learning», «artificial intelligence»).
- Прогон на title+abstract всех 28M документов.

### 3.2 Определение типов аффилиаций
- GRID: >99K организаций (типы: Education, Healthcare, Company, Archive, Nonprofit, Government, Facility, Other).
- Документ = «academia», если ВСЕ авторы с образовательной аффилиацией; «industry», если все с промышленной; смешанные — «collaborative effort».

### 3.3 Классификация промсекторов
- **INDUSO:** создан из аффилиаций авторов/патентообладателей: GRID → Wikipedia → DBpedia (About:Purpose, About:Industry) → 699 секторов → ручное слияние экспертами → **66 секторов** в двухуровневой иерархии (27 первого уровня, 39 второго). Связаны с исходными 699 через wasDerivedFrom (PROV-O).
- Unsupervised классификатор: аффилиация → GRID → DBpedia → INDUSO (+супер-категории). Пример: «Apple Inc, Cupertino» → GRID Apple → DBpedia (industry: Computer_hardware, Consumer_electronics) → «Electronics», «Manufacturing», «Financial», «Computing and IT» + супер-категории.

## 4. AIDA Dashboard

- Веб-приложение на AIDA; фокус — масштабируемость (средний сервер, много пользователей).
- **Архитектура:** back-end (Python) + front-end (HTML5/JavaScript). Back-end периодически предвычисляет аналитику и представляет каждую конференцию как **один JSON-файл**. Front-end загружает JSON и строит интерактивные представления. Лёгкая, но без live-запросов; предвычислено много аналитик/ранжирований.

### 4.1 Back-end: AIDA Conference Dataset
- Для каждой конференции: общие метрики (имя, акроним, годы, число публикаций/цитирований; **h-index, h5-index, impact factor за 2 года**), топ-100 авторов/организаций/стран/тем по публикациям и цитированиям (с h-index/h5-index для авторов/организаций), динамика академия/индустрия, фокус-области.
- **Fingerprint topics:** топ-100 тем, получивших в конференции % публикаций/цитирований выше среднего по CS (разница распределений конференции и всего CS). Пример: «machine learning» — 40% для NeurIPS (60% статей NeurIPS vs 20% в CS).
- **Фокус-области (Algorithm 1):** определение самой репрезентативной темы + её супер-тем. Сортировка тем по публикациям; фильтр whitelist; итерация: кандидат = тема; если под-тема — потомок кандидата И impact/candidate_impact > subtopic_thr (0.6 в прототипе), кандидат = под-тема; возврат последнего кандидата + супер-темы. Пример: NeurIPS — Neural Networks (2-е место за 5 лет), Machine Learning (2-е), Artificial Intelligence (5-е).
- Whitelist: 166 фокус-областей, ассоциированных с ≥5 конференциями. Обработка — несколько минут на среднем сервере, раз в год (offline).
- Обновление датасета: каждые 2 месяца (back-end), релизы каждые 6 месяцев.

### 4.2 Front-end (8 вкладок)
1. **Overview:** период активности, всего публикаций/цитирований, h5-index, средний h-index организаций/авторов, средние цитирования; фокус-области и ранги (средние цитирования за 5 лет); графики публикаций/цитирований, главные авторы/организации (10 лет), топ fingerprint-темы.
2. **Citation Analysis:** эволюция impact factor, средних цитирований, ранга/перцентиля в фокус-областях (NeurIPS — топ-2 в Neural Networks/Machine Learning, топ-10 в AI за 20 лет). Используется редакторами Springer Nature.
3. **Organizations:** главные институты по публикациям/цитированиям/средним цитированиям; фильтр по типу (академия/индустрия/все); bar-chart (период) или line-chart (по годам).
4. **Authors:** главные исследователи (публикации, цитирования, средние цитирования; сортировка по h-index/h5-index). Для молодых конференций без сильного цитатного рекорда.
5. **Countries:** Chart view (страны по публикациям/цитированиям) и Map view (мировая карта).
6. **Topics:** main topics и fingerprint topics; % публикаций с темой и цитирования.
7. **Related Conferences:** сравнение со всеми конференциями тех же полей (публикации, цитирования, средние цитирования; контекст полей). **Самая полезная вкладка по опросу (9/10).**
8. **Industry:** публикации/цитирования академии/индустрии/коллабораций; анализ промсекторов (% публикаций/цитирований компаний по секторам).

## 5. Оценка

### 5.1 Количественная (2 задачи классификации)
- **Фокус-области:** два human-crafted gold standard: (1) 50 конференций, 5 прямых под-тем CS (AI, Computer Hardware, Software Engineering, Internet); (2) 50 конференций, 5 под-тем AI (Machine Learning, Genetic Algorithm, Formal Logic, Knowledge Based Systems, Multi-agent System). Аннотация 3 сеньор-исследователями; majority voting (без случаев 3 разных ответов).
  - **Средний F1: 89.9% (первый) и 93.8% (второй).** Средний F1 (по абстракту) — **91.8%**.
  - Статистика: Cohen's κ для mixed pairs human-algorithm = **0.83** (95% CI 0.76–0.91); для пар людей = 0.77 (95% CI 0.68–0.86). CI перекрываются → авто-результаты не отличаются от экспертов.
- **Промсекторы:** 100 организаций (20 на сектор) из 5 классов (telecommunication, healthcare, automotive, computing and IT, electronic); 3 сеньор-исследователя; majority voting.
  - **Средний F1 = 87.5%.** Cohen's κ human-algorithm = 0.79 (95% CI 0.69–0.88); человеческие пары = 0.86 (95% CI 0.79–0.84). CI перекрываются → не отличаются от экспертов.
- CSO Classifier уже был оценён в [49] (отлично против state of the art) — здесь не повторяли.

### 5.2 User study (10 сеньор-исследователей)
- Состав: Open University UK (2), University of Cagliari (3), CNR (1), FIZ Karlsruhe (2), University of Paris 13 (1), Institute for Applied Informatics (1); 4 женщины/6 мужчин; в среднем 7.8 лет опыта (4 — ≥13); темы: AI, NLP, Digital Libraries, Semantic Web, Robotics, IR, HCI, Computer Vision, Theoretical CS.
- Процедура: презентация (~15 мин), задание — анализ двух конференций своей области, опрос из 5 частей.
- **SUS: 87.5/100 = A+, 98-й перцентиль.** Пользователи: легко использовать (4.5±0.71), хорошо интегрированные функции (4.6±0.51), не сложно (1.5±0.71), не нужна помощь (1.2±0.42), уверенность (3.9±0.99), готовность использовать часто (4.2±0.78), быстрое обучение (4.5±0.97), мало новых концептов (1.4±0.97), непротиворечивость (1.4±0.52), не громоздко (1.2±0.63).
- **Качество аналитики: 4.4±0.6 из 5** (конференции: AAAI, IJCAI, EMNLP, ACL, ISWC, SIGIR, TheWebConf, ICRA, TPDL и др.).
- **Открытые вопросы:** взаимодействие — легко/интуитивно (5 «easy to use», 2 «user friendly»); эффективность — все положительно (data-driven альтернатива стандартным рейтингам); сильные стороны — простота/юзабилити (7/10); слабости — мало кастомизации overview/related, нет ссылок на детали (авторы/темы), ограниченность CS-доменом, сложность UI, проблемы дизамбигуации имён; предложения — избранные конференции, алфавитная сортировка тем, более гранулярные темы, info-страница, поиск по фокус-областям, новая система рангов, Map View по периодам.
- **Фокус-области:** 8/10 «очень точны»; 2 — слишком высокоуровневые/пропущены.
- **Сравнение конференций:** 8/10 «очень точно и полно».
- **Лучшие функции (таблица 4):** Related Conferences (9/10), цитирования, авторы, организации; 4 — темы и промсекторы.

## 6. План устойчивости

- После декоммиссии MAG: переход на **Dimensions** (широкое покрытие CS, низкая стоимость) + **DBLP** (5 438 конференций) через маппинг по DOI; для веню без DOI (NeurIPS, INTERSPEECH) — схожесть строк заголовков/авторов + фильтры (нормализация, регистр, пунктуация) + год/название proceedings.
- Совместно со Springer Nature data science team.

## 7. Заключение

- AIDA Dashboard — веб-приложение для анализа/сравнения конференций (ML + Semantic Web + визуальная аналитика) на AIDA KG.
- Отличные результаты: авто-классификация фокус-областей и промсекторов F1 91.8%/87.5% (консистентно с экспертами); аналитика 4.4/5; SUS 87.5/100 (A+).
- Самая полезная функция — сравнение конференций по фокус-областям.

## Релевантность проекту

**4/5** — прямо релевантен **этапу 5 (дашборд)**:
- **AIDA Dashboard — образец для нашего Streamlit-дашборда:** вкладки (Overview, Topics, Related Conferences, Industry), сравнение по полям/временным окнам, эволюция тем, вовлечённость индустрии.
- **Идея «Related Conferences»** ↔ наш **граф связей между трендами** (общие темы = связи).
- **Характеристика по 14K темам CSO** — альтернатива BERTopic (если бы была онтология физики).
- **Fingerprint topics** (темы с % выше среднего по домену) — полезная идея для выделения «фирменных» тем нашего домена сверхпроводимости.
- **Пайплайн JSON на конференцию + лёгкий front-end** — архитектурный образец для нашего дашборда.
- Для жюри: показывает, как выглядит «промышленный» дашборд для анализа науки (контекст Газпромбанка).

## Ограничения работы

- Ориентирован на **Computer Science** (CSO) и **конференции** (не публикации в целом).
- Требует AIDA KG (дорогой в построении).
- User study — качественная оценка; нет жёстких количественных метрик дашборда как целого.
- Зависимость от MAG (декоммиссия) — решается переходом на Dimensions+DBLP.
