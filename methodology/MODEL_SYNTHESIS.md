# MODEL_SYNTHESIS.md — Единая модель «состоялся / не состоялся» (синтез проверок H23-H1-H18-H11)

> **Дата:** .
> **⚠️ РАБОЧИЙ ДОКУМЕНТ (living document):** модель — **гипотеза, выведенная на 9 калибровочных кейсах**
> (8 глубоких + 1 частичный). Она **может быть пересмотрена** при:
> (а) расширении числа глубоких кейсов (цель 20-25+, сейчас 9);
> (б) переходе в другую не-СП область (сейчас — только прикладная сверхпроводимость; поведение
> adoption/conversion/persistence в других полях не проверено);
> (в) строгой проверке по плану `results/S2_PROOF_PLAN.md` (контрольные поля, слепой тест).
> **Статус новизны:** компоненты модели — из литературы (Rotolo, Carley/Garner, Ebadi и др.),
> но **комбинация «scientometric emergence-скоринг + adoption/conversion как обязательные фильтры
> исхода» и её эмпирическое обоснование на ретро-кейсах — наш синтез** (см. §6 и
> `results/LITERATURE_REVIEW_MODEL.md`).
> **Назначение:** единый источник правды о модели для ML-прототипа, features_table и питча.

## 1. Вопрос, на который отвечает модель

**Дано:** технологическое направление, сигналы по нему в год окна (≈2018).
**Вопрос:** «тренд состоялся к 2026 / в развитии / не состоялся?» (метка исхода).

Модель — не «инвестировать/нет», а **«зарождающийся тренд подтвердился?»** (по ТЗ ЛЦТ).

## 2. Модель (двухэтапная)

**Этап 1 — скрининг кандидатов** (по всей публикационной базе, дёшево, recall-first):

```
кандидат_в_тренды ⇔  novelty_n × growth_n × impact_n  ≥  порог(этап 1)
```

**Этап 2 — верификация кандидата** (дорого, по одному, экспертные фильтры):

```
P(состоялся к 2026) ≈ f(
    impact_2018,        # наукометрический якорь (impact_n, см. §3a)
    adoption_2018,      # стадия внедрения: производство есть / только R&D (наш фильтр, H23)
    conversion_2018     # конверсия в патенты-ТНК + заказчик/рынок (наш фильтр, H23/H18; внешний критерий A5)
)
# ⭐ persistence (W3/W2) и novelty/growth — НЕ множители вердикта, а ОТДЕЛЬНЫЕ правила/фичи:
#    persistence < 1 при сильном росте → «всплеск» → ❌ (joint); novelty/growth — фичи Этапа 1.
```

**Почему два этапа (решение 2026-09-10):**
- **Этап 1 минимизирует ошибку II рода** (пропустить настоящий тренд) — низкий порог, широкие
  термины; ошибка I рода (ложный кандидат) здесь НЕ критична: её дешевле отбраковать на Этапе 2.
- **persistence — информация из будущего** (W3/W2 = 2020-22/2017-19 при окне 2018) → физически
  недоступна на Этапе 1 (look-ahead); в ядре скрининга ТОЛЬКО данные до года окна.
- Компоненты, доступные из публикационной базы сразу (novelty/growth/impact), ловят кандидата;
  adoption/conversion — дорогие прокси (патенты-ТНК, заказчики, IPO/M&A), живут на Этапе 2.
- Полная операционализация двухэтапного алгоритма — `methodology/METHODOLOGY.md §2а`;
  численная калибровка порога Этапа 1 на 9 кейсах — там же (§2а.3).

**Ключевой принцип (эмпирический, из 4 проверок):**
- **novelty + growth + impact** (Rotolo-ядро) — НЕОБХОДИМЫЕ условия ЗАРЯЖДЁННОСТИ (их хватает, чтобы
  СКРИНИРОВАТЬ кандидата — Этап 1), но **НЕ Достаточные для вердикта** (Этап 2);
- **persistence, adoption, conversion** — ОБЯЗАТЕЛЬНЫЕ фильтры вердикта, без которых модель даёт
  2 ложных вердикта из 9 (см. §4): persistence — как правило/фича (joint), adoption/conversion —
  как множители (IBAD/aircraft).

#### ⭐ Гейт возраста: novelty_n ≈ 0 при возрасте ≥ 20 лет (решение автора 2026-09-10)

**how:** `novelty_n = 1 − sigmoid((age−15)/5)` уже даёт ≈0 при больших age. Автор мягчает
границу: «если за 20 лет ничего не родилось, слабо верится что родится позже» →
**возраст ≥ 20 лет => novelty_n ≈ 0**, тема не проходит Этап 1 (screen ~ 0.01-0.05 < порог).

Численно при самой благоприятной комбинации (impact_n=1, growth ×10 → g_n=0.909):
| age | novelty_n | screen (N×G×I) | проходит? |
|---|---|---|---|
| 15 | 0.500 | 0.455 | ✅ |
| 20 | 0.269 | 0.244 | ✅ (но близко к 0.10) |
| 25 | 0.119 | 0.108 | ≈ порог |
| ≥26 | <0.1 | <0.09 | **❌ НЕ проходит** |

Ровно поэтому old-идеи (flying cars, zero-carbon aviation, SMES 30+) не попадают в
кандидаты даже при x10 росте — это ренессанс/холиваре, а не рождение тренда. Случай 30
лет и полный рост даёт screen 0.04-0.05 << 0.10.

**Важно (look-ahead стоп):** «возраст ≥ 20 => не тренд» — это и защита от ошибочной даты
рождения: если тема молодая по фундаменту (e.g. технология родилась на ВТСП в 1988, как
SMES после дособора) — ДАТИРОВАТЬ рождение по технологии, а не по идее (урок SMES 2026-09-10).

### 3a. Определение impact_n — нормировка цитатного якоря (решение автора 2026-09-10)

**impact_n** (нормализованный impact_2018, входящих цитат на ядро, S3_incoming_max):

```
impact_n = 1 − exp(−impact_2018 / 40)      (импакт в абсолютных цитатах)
```

**Ровно 1 подгоночный параметр: τ = 40 цитат.** Никаких сдвигов/дополнительных констант —
одна строка, понятная интуиция: «порог значимости ~40 цитат» (1/e ≈ 63% от максимума набирается
на 40 цитатах, 95% — на 120).

**Калибровка по якорям автора (что ожидаем от шкалы → что даёт τ=40):**

| Абсолютные цитаты | Ожидание автора | impact_n = 1−exp(−x/40) |
|---|---|---|
| 0 | 0 | 0.000 |
| 2 (1-3) | ≈0, <0.1 | 0.049 |
| 20 (15-30) | ≈0.5 | 0.393 |
| 65 (50-80) | ≈0.7 | 0.803 |
| 1000 | ≈1 (0.99) | 1.000 |
| 10000 | ≈1 (0.999) | 1.000 |

**Почему этого достаточно (обоснование «хорошего согласия»):** среднее квадратическое отклонение
по всем якорям SSE = 0.022 — при ОДНОМ параметре. Распиловка не требуется (в сравнении: shifted
Weibull с 3 параметрами даёт SSE 0.00003, но для жюри выигрыш в точности не стоит двух лишних
параметров — решение автора 2026-09-10).

**Что это меняет в модели (проверено на 9 кейсах, данные ESCORE_RECALC):**
- im_n на импактах кейсов: flux 133→0.964, jtwpa 117→0.946, ibad 100→0.918, ni 69→0.822,
  aircraft 58→0.765, joint 41→0.641, rce 9→0.201, smes 0→0, snspd 444→1.000;
- **разделение impact-порогом соло сохраняется 9/9**: min положительных = ni 0.822 > max
  отрицательных = aircraft 0.765 (при прежней τ=100 зазор был 69-58 в абсолютных цитатах;
  теперь — в нормализованных единицах, но зазор тот же по сути).
- escore (ранжирование) пересчитан на новой шкале — см. ESCORE_RECALC.md §9.

## 4. Эмпирическое обоснование (что дали 4 проверки на 9 кейсах)

| Проверка | Результат | Вклад в модель |
|---|---|---|
| **H23** (класс WISDOM) | 7/9; 2 контр-примера: IBAD (NSWK→✅), aircraft (weak→❌) | класс сигнала — базовая фича; **adoption** (IBAD vs SMES), **conversion** (aircraft vs SNSPD) |
| **H1** (рост) | ~5/9 (монетка); 3 дефекта роста | **persistence** (joint W3/W2=0.58 vs flux_pump 1.94); рост ≠ хайп (conversion); рост ≠ внедрение (adoption) |
| **H18** (lead time) | lead time не разделяет; ценность — корроборация | «ранний одиночный сигнал» = анти-сигнал; качество корроборации |
| **H11** (Rotolo) | 7/9; промахи = IBAD, aircraft | novelty/growth/impact — необходимое ядро; НЕ достаточно |
| **H2/H3** (S-кривая) | 6/9 (стадия, не исход) | стадия — ретроспективно; колонки НЕ добавляем (leakage) |
| **H10** (EScore) | **8/9 — лучший**; промах только IBAD | **ядро Этапа 1 = novelty×growth×impact** (без persistence — look-ahead); adoption/conversion — Этап 2 |

**Все 6 сходятся к одной ДВУХЭТАПНОЙ модели:** Этап 1 скрининг `novelty×growth×impact`
(из данных до 2018, recall-first) → Этап 2 вердикт `impact × adoption × conversion`
(+ persistence-правило W3/W2<1 → всплеск).
Это не декоративный вывод, а эмпирический факт: **одни и те же 2 контр-примера (IBAD, aircraft) ломают
все 6 литературных гипотез и чинятся одними и теми же фильтрами (adoption, conversion)**; ядро Этапа 1
(мультипликативное) дополнительно отсекает из КАНДИДАТОВ smes/rce, а ложных aircraft/joint сознательно
пропускает «на Мыло» — их отсекает Этап 2 (см. METHODOLOGY §2а.3: ошибка I рода на Этапе 1 не критична).

## 5. Правила-пороги (рабочие, будут калиброваться)

1. **Rotolo-ядро** (novelty+growth+impact) — предварительный гейт: если все 3 ❌ (как SMES, RCE) → ❌.
2. **adoption_2018 = 1** → сильный сигнал «состоялся» ДАЖЕ при слабых novelty/growth (IBAD-паттерн).
3. **conversion_2018 = 0 при growth = 1** → «PR-хайп» → ❌ (aircraft-паттерн); conversion отсекает хайп.
4. **persistence (W3/W2) < 1** при сильном росте в окне → «всплеск» → ❌ (joint-паттерн).
5. 🔶 «в развитии» = Rotolo-ядро ✅ + adoption/conversion ещё НЕ полные, но идут (JTWPA: коммерц. 2024+).

## 6. Новизна: что наше, что из литературы

### Что из литературы (компоненты)
- novelty/growth/impact + coherence: **Rotolo 2015**; **Carley/Garner 2018** (FUSE: novelty,
  persistence, community, growth — термин как единица);
- persistence (устойчивость): **Carley/Garner 2017-18** (контрпример «cold fusion» — всплеск без
  устойчивости); Rotolo («coherence persisting over time»);
- рост/новизна термина: **Ebadi 2022/2024** (WISDOM, KEM/KIM);
- слабый сигнал = редкая тема + ускорение: **Menning 2026**;
- коммерциализация как финальный критерий: **внешний критерий A5** (дисс. 2018) — «инновация ценна только
  при коммерциализации»; наша METHODOLOGY §IPO/M&A.

### Что НАШЕ (синтез и эмпирика)
1. **Комбинация** «scientometric emergence-скоринг (Rotolo/Carley) + adoption + conversion как
   ОБЯЗАТЕЛЬНЫЕ фильтры исхода» — в литературе не найдена (см. `results/LITERATURE_REVIEW_MODEL.md`).
   В emergence-литературе adoption/conversion не соединяются с детекцией; в диффузионной (Rogers,
   TRL) нет наукометрического emergence-скоринга.
2. **Эмпирический результат против Rotolo:** атрибуты Rotolo НЕ достаточны для предсказания исхода;
   два типа ложных трендов (внедрён-без-роста и PR-хайп-без-конверсии) Rotolo не различает.
3. **Ретроспективная калибровка** «сигнал 2018 → исход 2026» на реальных кейсах СП — такого
   валидированного набора в литературе по СП нет.
4. **Типология ложного тренда:** «госпрограммы без рынка» (SMES), «PR-гонка без конверсии» (008),
   «всплеск без persistence» (joint) — operationalized как фильтры.

## 7. Ограничения и что пересмотрит модель

| Ограничение | Как пересмотрит |
|---|---|
| 9 кейсов (8 глубоких), все — прикладная СП | расширение до 20-25 кейсов (в т.ч. фундаментальные: fluxonics, hydrides, topological_qubits) |
| Только СП-домен | проверка в не-СП области (контрольные поля из S2_PROOF_PLAN: CRISPR, перовскиты, LLM) — поведение adoption/conversion может отличаться |
| Колонки adoption/conversion/persistence добавлены в features_table вручную (субъективно) | формализация: adoption = патенты+фабрики+производители; conversion = commercial_events+ТНК-патенты (объективные прокси) |
| novelty по S3_birth ловит PR-кластеры (008) | уточнить: рождение технологии (по глубокой физике/инженерии), не по всплеску цитат вокруг события |
| Пороги (impact>50, W3/W2>1, возраст<15) — рабочие | калибровка на 20-25 кейсах / ML |
