# distilled_dataset/ — три валидационные базы (ядро согласованной позиции по ТЗ)

> Создано 2026-09-16. Решение автора: коммит-веха будет, когда появятся три базы данных.
> Позиция зафиксирована в `methodology/DEVIATIONS_FROM_TZ.md` (§3): наша задача — **>80% на
> дистиллированном датасете за вычетом явного хайпа, не-технологий и состоявшихся технологий**;
> дистиллированный датасет = то, что похоже на слабые тренды в 2026 году.

## Три базы

| Файл | База | Роль в методе |
|---|---|---|
| `01_weak_signals_2026.md` | **Слабые сигналы 2026** | Валидационная: множество текущих зарождающихся трендов (на 2026). На неё смотрим при оценке выдачи модели (>80%) — «что должно попасть в ТОП». Наполняется пайплайном (Этап 1 скрининг → Этап 2 верификация) + экспертизой автора |
| `02_weak_signals_2023_established_2026.md` | **Слабые сигналы 2023 → состоялись к 2026** | Обучающая/калибровочная: сигналы 2023 г., по которым мы ЗНАЕМ исход к 2026 (состоялся/в развитии). Аналог наших СП-ретро-кейсов на IT-домене; позитивный класс с известным исходом. Отбор полуавтоматический (наши слои → верификация автора) |
| `03_excluded_signals.md` | **Исключённые из рассмотрения** | Негативы/выбросы: элементы датасета организаторов, исключённые из дистилляции, С ОПИСАНИЕМ ПРИЧИН исключения (хайп / стандарт соответствия / проблема без решения / не-технология / состоявшаяся технология). Классы исключения — по нашей типологии ложных трендов + внешним критериям |
| `100_official_index.md` | Трекер 100 сигналов | Все 100 строк официального датасета со статусом дистилляции (база 1/2/3, обсуждается) |
| `data/official_100.json` | Машинный дамп | Полный машинно-читаемый дамп официального датасета для пайплайна |

## Связь с ТЗ и методологией
- **Официальный датасет организаторов:** `docs/official_docs/100_слабых_технологических_сигналов_сентябрь_2026.xlsx`
  (100 сигналов, 1 лист «Слабые сигналы»; №, технология, область, компании, почему слабый сигнал, стадия,
  тренд упоминаний, балл, источники; № — глобальный, области: Edge 16, Защита ИИ 16, Индустриальный ИИ 17,
  Инфраструктура ИИ 17, Роботы 17, Финтех 17). Доменные копии — `IT_calibration/*.xlsx`. Это ИСХОДНЫЙ
  МАТЕРИАЛ, не обучающая истина (см. DEVIATIONS §2).
- Дистилляция: их «+» → разбор по слоям (внимание/наука/инженерия/рынок/регуляторика) →
  распределение по базам 1/2/3. То, что «похоже на слабый тренд в 2026» → база 1; с известным
  исходом 2026 → база 2; остальное (хайп/стандарт/проблема/не-технология) → база 3 с причинами.
- Наши СП-кейсы (case_studies/): база №1 валидации (12 глубоких, стремимся увеличивать) — живёт
  в реестре `results/calibration/CASE_REGISTRY.md` и features_table, НЕ дублируется здесь.

## Процесс наполнения
1. Кандидат (из датасета организаторов или открытых источников) → разбор по слоям + экспертиза автора.
2. Распределение по базам с обязательной строкой «почему» (для базы 3 — развёрнутые причины).
3. Каждая строка любой базы — с паспортом источника (наименование, ссылка, дата, тип, язык, доверенность)
   — требование ТЗ §7.
4. Статусы: 🔶 кандидат / ✅ подтверждено автором / ❌ исключено (перенос в базу 3).
