## Призма проверки (по образцу уже согласованных EX)
- 🅐 **Стандарт соответствия** (как №51 AI-SBOM): драйвер — регуляция/требование, формат канонизирован, это адаптация, а не изобретение. → база 3.
- 🅒 **Проблема без решения** (как №76 memory poisoning, №82 FL межзаводское): нет доминирующего дизайна,
  существующие подходы не работают, «беспокойство без продукта». → база 3.
- 🅑 **Обещание-навеки / хайп** (как №34 SMR, №59 орбитальные ЦОД): не решены физические/экономические
  предпосылки (удешевление, охлаждение, цикл обновления), «внимание/капитал ≫ содержание». → база 3.
- 🅔 **Зрелая/состоявшаяся технология** (как №1 сжатие, №47 фотоника, №80 нейрочипы): мега-раунды/продукты
  уже есть → не «слабый сигнал 2026». → база 3 (или база 2 только при известном исходе 2023→2026).

**Главный урок (для методологии):** не каждый «слабый сигнал» в датасете организаторов — технология.
Критерий-фильтр: (1) это технология, а не стандарт/проблема/паттерн/маркетинг; (2) реализуемая (есть
физические/инженерные предпосылки, а не «нужно удешевление ×10/другая физика»); (3) при сравнении № из
РАЗНЫХ областей — не только общие игроки, но и ВИД технологии (edge-вычичисление ≠ облако ≠ паттерн):
совпадение компаний (Starcloud/Kepler у №18 и №59) НЕ означает дубль, если класс вычислений разный.
Вопрос автора ценен именно этим: проверка «технология ли это» включает и анти-дубль по виду, не только по игрокам.
